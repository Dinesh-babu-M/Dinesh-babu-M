THE ENGINEERING JOURNEY
Every system starts with a problem.

Sometimes it is a repetitive manual task.

Sometimes it is messy data.

Sometimes it is an application that needs a better architecture.

Sometimes it is a process that works today but will not scale tomorrow.

My approach is to understand the complete flow before deciding how to solve it.

   ↓
DESIGN

   ↓

I enjoy working across cloud engineering, data engineering, backend development, frontend applications and automation because real-world systems connect all of these layers.

THE DATA PROBLEM
Real-world data is rarely perfect.

It can contain:

NULL VALUES
DUPLICATES
WRONG FORMATS
INCONSISTENT VALUES
INVALID RECORDS
MISSING FIELDS
UNEXPECTED INPUT

Data engineering is therefore more than moving information from one place to another.

It is about creating a pipeline where data can become clean, validated, traceable and useful.

MY DATA PIPELINE
EXTRACT
   ↓
CHECK
   ↓
CLEAN
   ↓
TRANSFORM
   ↓
VALIDATE
   ↓
LOAD
   ↓
VERIFY
   ↓
REPORT

DATA QUALITY QUESTIONS
[01] DID THE DATA ARRIVE?

[02] IS THE DATA VALID?

[03] WAS THE DATA TRANSFORMED CORRECTLY?

[04] CAN THE OUTPUT BE TRUSTED?

[05] CAN THE PROCESS BE REPEATED?
